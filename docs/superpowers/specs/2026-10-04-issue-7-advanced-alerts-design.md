## 1. 目的與範圍

在既有單次上下限提醒上，加入短期漲跌、可重複提醒與冷卻時間，讓使用者從程式介面查詢提醒紀錄。保留 #3 的單次提醒、手動重設、舊設定與舊紀錄相容性。

每個幣種提供四個互相獨立的條件：價格上限、價格下限、短期上漲、短期下跌。每個條件各有單次／可重複策略、觸發狀態與冷卻設定。漲、跌條件可分別設定時間區間及百分比。

本次不加入任意數量規則、指標、交易功能、紀錄匯出或歷史資料庫。使用既有 Binance 公開 ticker；短期判斷不依賴視窗、走勢顯示或歷史 REST 成功。

## 2. 比較基準與有效資料

### 2.1 短期漲跌定義

- 時間區間為整數 1–60 分鐘；門檻為正百分比，上漲與下跌都輸入正數，方向由條件類型決定。
- 計算式為 `(目前價格 / 基準價格 - 1) × 100`，使用 decimal 未四捨五入的結果判斷。
- 以上漲條件而言，結果大於或等於門檻即符合；以下跌條件而言，結果小於或等於負門檻即符合，包含邊界。
- 基準是目前行情事件時間減去設定區間後，該時刻以前最近一筆有效即時 ticker。基準距離目標時刻最多 5 秒，禁止使用目標時刻之後的資料、插值或任意較早的價格。
- 範例：5 分鐘下跌 2%，基準 100，現價 98 即符合；比較的是五分鐘前的價格，不是區間內最高價或 Binance 的 24h 漲跌幅。
- 使用行情事件時間選取資料，使用可注入的 UTC 時鐘判斷新鮮度及冷卻；畫面與紀錄時間以本機時區顯示。

### 2.2 資料完整性

- 只用有效即時 ticker 建立短期序列；REST 啟動快照仍可判斷上下限，但不能當作短期基準。
- 價格必須大於零，事件時間必須有效且不晚於接收時間 5 秒、也不早於接收時間 5 秒。短期序列拒絕相同或倒退的事件時間。
- 每個幣種獨立維護序列；相鄰有效事件間隔大於 5 秒視為資料缺口，清除該幣種短期序列。
- 收到 Connecting／Disconnected、feed 世代替換或幣種停用／移除時，清除相關序列。重新連線、重啟或重新啟用後，等待完整設定區間重新累積。
- 基準到目前報價必須屬於同一段連續有效資料。缺少基準或發現資料缺口時不計算、不通知，也不能以無效資料替可重複條件重新武裝。
- 沒有有效資料時顯示「等待完整 N 分鐘報價」，避免使用者將等待狀態誤認為條件已符合。
- 依啟用的短期條件保留各幣種所需最長區間及 5 秒基準容差；超過保留區間的樣本淘汰，沒有短期條件時不保留序列。
- 可獨立實作 ticker 時序緩衝：現有一分鐘 candle 無法提供指定秒數的比較基準，也不足以證明 ticker 接收連續，因此不直接以走勢 candle 判斷。本 issue 允許共用資料，但不強制。

## 3. 提醒狀態機

### 3.1 單次策略

- 四個條件預設單次，冷卻預設 0 分鐘；新短期條件預設停用。
- 首筆有效上下限報價可以觸發，保留 #3 行為；短期條件須先滿足完整資料規則。
- 成功提交後保留已提醒狀態；回到門檻內、重啟、改門檻或重連都不能自動重設。只有使用者明確重設並儲存才能再次提醒。

### 3.2 可重複策略

- 冷卻時間為整數 0–1440 分鐘。各條件冷卻從最後成功提交通知的時間開始。
- 新條件／明確重設後為已武裝。上下限首次有效報價若符合可通知，短期首次完整比較若符合也可通知。
- 一次成功提醒後解除武裝；上限必須觀察到 `< 上限`，下限必須觀察到 `> 下限`；漲跌條件必須觀察到有效計算結果回到未符合區，才重新武裝。等於門檻仍屬符合區。
- 已武裝條件下一次進入符合區形成突破。如果冷卻已結束，通知並解除武裝；冷卻期間發生的突破不通知，但仍解除武裝，需再次回到未符合區後突破。不能在持續符合時因冷卻結束而補發。
- 對已成功提醒的可重複條件，啟動／重連／資料缺口後先等待有效的未符合觀察再武裝；不將中斷前的已武裝狀態視為中斷期間沒有突破的證據。保存已提醒及最後成功通知時間，確保重啟不立即重複通知。
- 修改門檻、區間或策略不能清除已提醒及冷卻時間。切換到可重複且過去曾提醒的條件，保守地等待有效未符合觀察；切換到單次且曾提醒的條件仍為已提醒。
- 手動重設只清除指定條件的已提醒、最後通知時間及武裝狀態，重新允許首次符合；不刪除紀錄。整個幣種重設涵蓋四個條件。
- 短期區間修改後，該條件重新等待完整比較區間；不能把修改前已符合／未符合狀態當作新條件的突破。

### 3.3 並行、保存與失敗

- 延用 PriceAlertService 的單一序列化入口，判斷、狀態變更、儲存、紀錄追加、通知提交及還原都在同一 gate 中完成。
- 保存成功提醒狀態與時間，再保存完整紀錄，最後提交 Windows 通知；每次成功提交對應一筆紀錄。
- 任何階段失敗都還原該次交易以前的全部條件狀態，包括已提醒、武裝及冷卻時間，以及既有紀錄。不能只將已提醒布林值清為 false。
- 失敗的突破不視為已消耗；後续有效符合報價可重試同一通知。成功後持續符合則不重複。
- 冷卻期間消耗突破及未符合時重新武裝的持久狀態變更也須安全保存；保存失敗則還原並重試，不能錯誤宣稱狀態已保存。
- 延用現有 pending rollback 保護：還原失敗時阻止新提醒提交，恢復寫入後先完成還原。
- 時鐘回撥不能提前解除冷卻；若現在早於最後成功提醒時間，仍視為冷卻中。
- 保留既有跨設定檔、歷史檔與 Windows 通知非原子操作的限制；不承諾強制斷電時恰好一次送達。

## 4. 模型與向後相容

- 保留原有 `UpperPrice`、`LowerPrice`、`UpperTriggered`、`LowerTriggered` 及 AlertType 的 Upper／Lower JSON 值。
- 增加 Rise／Fall 類型。上下限各自增加策略、冷卻及執行狀態；短期條件增加區間、正百分比門檻、策略、冷卻及執行狀態。
- 執行狀態可包含最後成功提醒時間、已武裝及已提醒。設定 Copy、Normalize、編輯草稿合併、重設與鈴鐺狀態需涵蓋四個條件。
- 舊設定缺少新欄位時使用單次、0 冷卻、短期停用；既有已提醒值完整保留。非法新值須有可理解的驗證錯誤，不能靜默變成較積極的提醒策略。
- 編輯視窗打開後的行情提醒可能更新狀態；儲存草稿只套用使用者修改的條件參數，執行狀態以服務即時值為準，只有明確重設可覆寫。
- 一般設定儲存仍完整保留最新警示參數與狀態；不同幣種警示視窗互不影響。
- AlertHistoryEntry 保留舊五個欄位；新波動紀錄額外記錄時間區間、百分比門檻、基準價格、基準行情時間、觸發行情時間及實際帶正負號漲跌幅。
- 上下限紀錄使用原有 TargetPrice；波動紀錄不將百分比塞入價格欄位，新欄位提供其門檻，TargetPrice 可為 null。舊紀錄的正目標價保持原樣。
- 讀取歷史時依類型驗證必要欄位，舊上下限紀錄不要求新增欄位；未知類型或損壞資料報錯並保留原檔。

## 5. 使用者介面

### 5.1 價格警示編輯

- 延用每幣種獨立價格警示視窗，四組條件依序為上限、下限、短期上漲、短期下跌，內容可捲動。
- 每組提供門檻、策略、狀態與重設；可重複策略顯示冷卻分鐘輸入。短期組另外提供區間分鐘。
- 門檻留空停用該條件；上下限為正 USDT 價格，短期為正百分比。區間及冷卻使用整數，驗證訊息指出條件及允許範圍。
- 狀態清楚區分未設定、等待完整區間、等待觸發、已提醒、等待回到未觸發區、冷卻中及待儲存重設。
- 在短期設定附近解釋「與 N 分鐘前有效報價比較；斷線後重新累積」，在重複設定附近解釋「回到未觸發區後再次突破；冷卻期間突破不補發」。
- 儲存生效、取消放棄，延用深／淺色主題、鍵盤操作及可及性名稱。重設所有條件按鈕保留原使用方式。
- 鈴鐺的設定／曾提醒摘要涵蓋四個條件；工具提示指出具體類型，避免可重複條件曾提醒就被誤解為永久停用。

### 5.2 提醒紀錄視窗

- 系統匣新增「提醒紀錄」入口，價格警示視窗也提供同一入口；全程只建立一個紀錄視窗，再次開啟重用並還原最小化。
- 表格顯示幣種、條件類型、目標價或百分比門檻、實際觸發價及本機觸發時間；波動列額外顯示區間、基準價與實際漲跌幅，可使用詳細區補足窄視窗內容。
- 幣種篩選包含歷史出現過的幣種，即使目前已移除；類型篩選提供全部及四種條件。
- 提供起始／結束日期（本機日曆日，含選定結束日），預設不限制日期；起始晚於結束顯示錯誤，不默默交換。
- 預設時間由新到舊，可切換為舊到新；同時刻維持檔案原始順序。比較以 DateTimeOffset 的實際時刻為準。
- 成功追加紀錄後更新開啟的紀錄視窗，保留目前篩選及排序；另提供重新載入按鈕。
- 空檔顯示「尚無提醒紀錄」；篩選沒有結果顯示「沒有符合篩選的紀錄」。
- 損壞或讀取失敗顯示具體可理解的錯誤與重試；不覆寫原檔，若先前有成功載入資料則保留並標示尚未更新。
- 主窗隱藏後仍可操作，跟隨即時主題；程式結束時一併關閉並取消訂閱。

## 6. 整合邊界

- Core 中新增獨立的有效報價時間緩衝及波動計算，無 WPF 依賴；PriceAlertService 負責四類條件狀態機及交易。
- App 把報價來源、行情時間、連線狀態及 feed 世代傳給提醒服務；不得從走勢可見性推導是否監控。
- 保留舊上下限呼叫／測試的相容入口；新即時入口能分辨 REST 快照及串流，避免將歷史快照當成新的短期樣本。
- 新的紀錄 ViewModel 負責篩選、排序與載入狀態；WPF Window 負責呈現，依現有 manager 模式處理視窗生命週期。
- 設定存檔、提醒狀態、通知內容、App 關閉時等待待處理提醒，以及一般設定交錯儲存，都需延續既有保護。

## 7. 驗證與完成條件

採受控 UTC 時鐘、行情事件時間、HTTP／串流及暫存檔，不使用真實價格或睡眠等待測試門檻。

1. 舊設定／紀錄載入、Copy／Normalize、新值驗證及已提醒狀態保留。
2. 四個條件門檻邊界、單次／重設、策略修改、各自獨立狀態。
3. 基準恰好在目標時刻、5 秒容差內／外、正負漲跌、零價、倒序及同時間事件、過期／未來事件。
4. 區間不足、5 秒缺口邊界、斷線／重連、重啟及區間修改不誤報，隱藏走勢與主窗仍能提醒。

6. 高頻並行報價至多提交一次；四個條件及不同幣種互不阻塞其邏輯狀態。
7. 保存、紀錄、通知與還原失敗，完整執行狀態還原及之後重試；不成功提交不得留下一筆成功紀錄。
