# Issue #6：行情視覺化與快速查看設計

- 日期：2026-10-04（Asia/Taipei）
- 來源：[GitHub issue #6](https://github.com/kimx-solutions/BnUsdtTicker/issues/6)
- 狀態：使用者已確認介面與共用資料方案，並以「開始」確認本正式規格；實作計畫待審閱。
- 開發起點：`e8166c14a9237af0ba6db3952dc5f034920cef78`。

## 1. 目的與已確認的方案

讓使用者在原本小巧的 Windows 報價視窗看出近一小時或一天的價格方向，並快速查看個別幣種的詳細行情。維持不需要 Binance 帳號、API Key 或個人資訊的使用方式。

使用者已確認以下方案：每列報價下方放置迷你曲線；頂部統一切換 1h／24h；點幣種開啟獨立詳情視窗；一分鐘行情快取由歷史資料初始化、串流持續更新。現有排序、價格警示、拖曳及 Fix／Float 操作需持續可用。

其他曾考慮的配置是新增走勢欄，但會壓縮目前 390 DIP 寬度內的價格與漲跌幅，因此採用列下方曲線。

## 2. 本次範圍

- 每個啟用幣種顯示近 1h／24h 的迷你走勢，可隱藏走勢。
- 幣種詳情顯示現價、24h 漲跌幅、最高價、最低價、成交量及資料時間。
- 詳情視窗提供在預設瀏覽器開啟該幣種 Binance USDT 現貨頁的按鈕。
- 歷史資料初始化、即時更新、重連補齊、請求限流及可理解的錯誤狀態。
- 一份不依賴 WPF 的共用行情快取，供本次畫面及後續 #7 的波動提醒使用。
- 顯示偏好保存與舊版設定相容；受控資料測試、實際 WPF 畫面檢查及使用文件更新。

視窗可調整大小仍由 #8 處理；進階提醒與紀錄查詢由 #7 處理；分組及持倉由 #9 處理。本次不加入技術指標、帳戶同步、下單、完整交易介面或歷史資料庫。

## 3. 使用者介面

### 3.1 報價視窗

- 保留原本標題、排序欄位、鈴鐺、現價、24h 漲跌幅及底部控制項。
- 標題與欄位間增加簡潔的走勢工具列：`1h`、`24h` 與顯示／隱藏走勢操作。
- 時間範圍統一套用所有報價列；預設顯示走勢、選擇 `1h`。切換只改變快取的檢視範圍，不重新抓取同一份歷史資料。
- 每列下方放置高度約 32 DIP 的曲線，橫向使用該列可用空間。行高與捲動仍遵循緊湊顯示及目前視窗高度限制；不增加固定寬度。
- 曲線顏色依所選區間第一筆與最後一筆價格比較；這可能與旁邊的 24h 漲跌幅不同，工具提示說明兩者時間範圍。
- 幣種名稱改為可操作的詳情入口，滑鼠提示「查看 BTC 行情」等明確文字，支援鍵盤焦點及可及性名稱。
- 曲線工具提示顯示時間範圍、有效資料起訖與載入狀態；部分資料不冒充完整 24 小時。
- 關閉走勢後隱藏曲線及其狀態列，仍保留可重新開啟的操作。現價、詳情入口與警示仍可使用。
- 按鈕與新的互動區域不啟動視窗拖曳；其餘原本可拖曳區域保留移動功能。

### 3.2 幣種詳情視窗

- 點幣種名稱開啟獨立視窗，與目前每幣種價格警示視窗的操作方式一致。
- 同一幣種只建立一個詳情視窗；再次開啟會還原最小化狀態並將既有視窗帶到前景。不同幣種可同時開啟。
- 顯示完整交易對、現價、24h 漲跌幅、24h 最高／最低價、幣種成交量及 USDT 成交額。成交量與成交額明確標示單位。
- 「24h」表示 Binance 提供的滾動 24 小時統計，不表示台北時間當天的統計。
- 顯示同一份快取產生的較大走勢圖，時間範圍沿用主畫面選擇；主畫面隱藏走勢時，詳情仍可載入並顯示走勢。
- 顯示報價及走勢各自的更新時間、連線及資料完整性狀態。
- 提供「開啟 Binance 交易頁」與關閉按鈕；歷史載入失敗時可重試，重試仍遵守共用限流與去重。
- 深／淺色切換即時套用至所有已開啟的詳情視窗，包括原生視窗框。
- 幣種被刪除或停用時關閉對應詳情視窗；程式結束時關閉所有詳情視窗並停止相關工作。
- 維持 Float 模式失焦隱藏主視窗的既有行為；詳情是獨立視窗，仍可繼續查看。

### 3.3 狀態顯示

現價與歷史走勢狀態獨立。歷史載入失敗不能阻止報價及價格提醒。

| 狀態 | 顯示與行為 |
| --- | --- |
| 初次載入 | 「載入走勢中」，不製造示意曲線 |
| 完整資料 | 顯示曲線及實際有效資料時間 |
| 部分資料 | 顯示已有曲線並標示「資料不足」或「補齊中」 |
| 少於兩筆有效價格 | 顯示資料不足提示，不畫出虛構趨勢 |
| 斷線或資料逾期 | 保留最後曲線，標示舊資料與最後更新時間 |
| 歷史查詢失敗 | 現價繼續更新；走勢保留既有資料並顯示失敗／重試入口 |
| 缺少行情詳細欄位 | 該欄顯示「—」，不將缺值當作零 |

除了連線狀態，也檢查各幣種最後事件時間：即使連線仍顯示 Connected，超過 60 秒未收到該幣種有效行情仍標示資料逾期。可注入時間來源供測試，避免以實際等待驗證。

## 4. 資料來源與模型

### 4.1 24 小時行情

- 擴充目前 ticker 模型，增加可缺省的 `HighPrice24h`、`LowPrice24h`、`Volume24h` 與 `QuoteVolume24h`。
- REST 取自 `highPrice`、`lowPrice`、`volume`、`quoteVolume`；現有 ticker 串流取自 `h`、`l`、`v`、`q`。沿用目前已取得的完整 ticker，不新增每個詳情視窗的輪詢。
- 必要價格及時間欄位沿用目前驗證。缺少或損壞的選用詳細欄位顯示不可用，不因此丟棄有效現價；不沿用較早統計假裝是目前報價的詳細資料。
- 數值使用 `decimal`，時間由 Binance Unix 毫秒轉為 UTC。畫面才轉為本機時區。
- 舊測試與呼叫端只提供原本四個 ticker 欄位時，仍可正常工作。

### 4.2 一分鐘 K 線

- 新增 Core 的一分鐘 K 線模型，保留幣種、開盤／結束時間、OHLC、成交量、是否收盤及資料版本時間。
- 迷你曲線使用收盤價形成折線；尚未收盤的一分鐘使用串流最新 close，並保持其為未收盤資料，不把最後成交價寫成已收盤 K 線。
- 歷史使用公開 `GET /api/v3/klines`，`interval=1m`；即時使用 `<symbol>@kline_1m`。
- REST 每次最多 1000 根；初始近 24 小時加一根邊界資料以固定起訖時間分頁，通常最多兩頁。不能只取 1000 根就宣稱有完整一天資料。
- K 線以開盤時間唯一識別；同一根的串流更新取代該根資料，不新增重複點。
- 格式、時間順序、幣種、間隔及價格需驗證；不合格事件不污染共用快取，後續有效事件仍可恢復。

參考：[Binance REST 行情](https://developers.binance.com/docs/binance-spot-api-docs/rest-api/market-data-endpoints)與[現貨行情串流](https://developers.binance.com/docs/binance-spot-api-docs/web-socket-streams)。

## 5. 元件責任與資料流程

維持 Core 與 WPF 的既有邊界，不新增繪圖套件或產品依賴。

| 元件 | 責任 |
| --- | --- |
| 歷史行情介面與 REST 實作 | 取得及驗證分頁 K 線、支援取消及 HTTP 失敗處理 |
| 共用行情快取 | 每幣種儲存、合併及裁切有序 K 線，回傳不含 WPF 的不可變快照 |
| 歷史載入協調器 | 請求去重、限流、重試、重連補資料、載入狀態與生命週期 |
| 既有 WebSocket／MarketFeed | 同一 combined 連線分派 ticker 與一分鐘 K 線事件，沿用既有重連與取消機制 |
| Ticker／詳情 ViewModel | 顯示偏好、格式化行情、選擇時間範圍及資料狀態；不直接發送 HTTP |
| WPF 走勢控制項 | 將時間與價格映射成折線，處理尺寸、配色及資料缺口；不擁有行情資料 |
| App／視窗管理 | Dispatcher 交付、視窗去重、瀏覽器啟動、設定保存及結束清理 |

典型流程：主報價先啟動 → ticker 更新現價／詳細欄位；K 線串流更新共用快取 → 背景歷史查詢填入既有區間 → ViewModel 取同一快照供主畫面與詳情繪圖。

歷史工作不放在主報價初始 REST 之前，也不因某個幣種失敗而中止其他幣種。後續 #7 可讀取同一份 Core 快照，無須從圖形或 WPF ViewModel 取得資料。本次不實作波動提醒。

## 6. 合併、範圍與重連

- 每個啟用幣種有唯一快取，保存近 24 小時及必要邊界 K 線，硬上限 1500 根；移除／停用幣種會釋放其快取及載入工作。
- 初始化或補資料捕捉固定 UTC 起訖時間。分頁使用上一頁最後開盤時間加一分鐘作為下一頁起點，避免重複頁或無限迴圈。
- 歷史請求記錄發送時的資料版本時間；回應可補缺少的舊 K 線，但不得覆蓋發送之後到達的較新串流資料。同一根已收盤資料不能被較早的未收盤事件還原。
- 已收盤 K 線的圖形取樣時間使用結束時間；未收盤 K 線使用最新事件時間，避免畫到未來。
- 1h／24h 以目前 UTC 時間為右界、固定長度為橫軸，不把不足的資料拉伸成整段範圍。取一個左界之前的相鄰點，僅在不存在資料缺口時用於邊界銜接。
- 斷線區間不以直線連接成看似已知的走勢；缺口與「補齊中／資料不足」狀態需可辨識。
- 有曲線顯示需求時，重連後從最後完整 K 線附近重疊補抓至現在；若缺口超過保留範圍，重建目前 24 小時區間。沒有顯示需求時記住缺口，待曲線再次顯示時補抓。補抓與新串流更新並行，使用同一合併規則。
- 收到舊 feed 世代、已停用／刪除幣種或取消工作的回應時忽略，不重新建立已釋放的資料或操作已關閉視窗。
- 主畫面與詳情讀取相同資料、獨立繪圖；排序僅移動既有 row，不重建行情快取。

## 7. 請求與生命週期

- 對所有啟用幣種一次訂閱 ticker 與一分鐘 K 線，主畫面隱藏走勢不影響既有報價／提醒及串流快取。訂閱仍需遵守 Binance 的串流數量限制。
- 歷史初始化只在需要顯示曲線時載入；主畫面關閉走勢且沒有詳情視窗時，不發起新的歷史初始化。已有快取保留並隨串流維護。
- 切換時間範圍、重複開啟詳情及多個畫面需求共用同一載入任務，不產生相同幣種／區間的並行重複請求。
- 歷史請求限制最多兩個同時進行，起始請求至少間隔 250 毫秒；取消等待者不遺漏限流資源的釋放。
- 暫時性網路／伺服器失敗最多再重試三次，延遲 1、2、5 秒；不對無效幣種等永久錯誤重試。
- HTTP 429／418 依 `Retry-After` 或有界退避暫停所有歷史請求；手動重試也不能繞過共用暫停。請求沒有結束前，不加入重複工作。
- 切換幣種設定沿用目前取消並等待舊 feed 的流程，補抓與初始化也包含在可追蹤、可取消的生命週期內。
- 關閉一個詳情視窗僅釋放其畫面訂閱，不取消其他畫面仍需使用的共用請求。
- 正常結束會取消並等待 feed 及歷史工作，停止狀態計時器及畫面通知，再釋放視窗、tray 與 HttpClient。

## 8. 圖形與效能

- 以 WPF 原生繪圖呈現；Core 回傳時間／decimal 價格資料，WPF 層才轉為繪圖座標。
- 同一個時間範圍維持時間比例，不均勻分布有缺口的時間點。零高度／零寬度跳過繪圖；所有價格相同時畫水平線，不除以零。
- 每個圖形依可用寬度將資料裁減至最多約 300 點，保留區間首尾及各區段高低點，且不跨缺口連線。原始快取不因繪圖裁減而丟失，供後續計算使用。
- 圖形更新最多每秒一次，最新 ticker 價格及現有價格提醒仍按原本有效報價處理，不被圖形節流延遲。
- 畫面不可見時停止不必要的繪圖，關閉視窗／停用幣種後釋放事件訂閱，避免多次開關後累積回呼。
- 深淺色有足夠的曲線及文字對比；空資料、部分資料與斷線狀態在緊湊列高及長清單下仍可讀。

## 9. 設定與瀏覽器入口

- `UiSettings` 新增 `ShowSparkline`（預設 true）與 `SparklineRange`（預設 1h、只允許 1h／24h）。主畫面即時操作後保存；一般設定畫面亦可調整。
- 擴充 `Copy()`、設定驗證及 SettingsViewModel。舊設定缺少新欄位時使用預設值；未知 range 回到 1h，不因這個選用欄位丟棄使用者幣種或警示。
- 若一般設定視窗開啟後，使用者已在主畫面切換走勢偏好，一般設定儲存需保留沒有在該編輯器中修改的新偏好；若有明確編輯則套用編輯值。取消編輯不影響即時操作。
- 外部連結只從已驗證的 USDT 現貨幣種組成 `https://www.binance.com/en/trade/{ASSET}_USDT?type=spot`，不接受任意 URL。
- 將連結產生與系統瀏覽器啟動分開，便於受控測試，不在測試時真的開啟瀏覽器。啟動失敗在詳情顯示錯誤，視窗及行情維持可用。
- 同步更新 README、設定範例及必要的驗收文件。
