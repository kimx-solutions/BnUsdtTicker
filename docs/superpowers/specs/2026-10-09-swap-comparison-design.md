# 換幣相對盈虧追蹤規格

- 日期：2026-10-09（Asia/Taipei）
- 狀態：使用者已指示開始實作；實作與驗證紀錄見 docs/verification.md。GitHub issue 因連接器權限不足尚未建立。
- 相關工作：#9 自選分組與手動持倉追蹤。
- 使用者需求：原本 100 NEAR 換成 20 QNT，持續查看現在換回 NEAR 可多／少幾顆，以及這個差距相當於多少 U。

## 1. 目標與計算語意

以「如果當初繼續持有原幣」為比較基準，呈現換幣決策的相對盈虧。方向固定為 A → B；A 是換出幣與比較單位，B 是換入後持有的幣。

本功能的「USDT 差額」是現在 B 的市值減去原本 A 數量的現在市值，不是相較原始投入 USDT 的絕對損益。介面使用「換幣差額／相對報酬」文字，與既有持倉平均成本損益分開。

U 在此明確指 USDT。報價取 A/USDT 與 B/USDT 的公開現貨行情，交叉換算；不要求交易所存在 B/A 直接交易對，也不代表實際可成交報價。

## 2. 第一版範圍與操作流程

新增全域「換幣比較」獨立視窗，可從報價視窗與系統匣開啟；重複開啟時重用視窗。沿用深／淺主題與既有輔助視窗的 Fix／Float 行為，主報價窗隱藏後仍可查看。

1. 點「新增」，輸入換出幣、換出數量、換入幣、實際換入數量、換幣時間及選填備註。
2. 儲存後建立一筆固定方向的比較紀錄，並訂閱兩邊行情。
3. 清單持續顯示現在可換回數量、幣數差額、USDT 差額及相對報酬率；詳情顯示公式、兩邊現價與報價時間。
4. 可編輯、取消編輯、刪除，以及啟用／停用追蹤。停用紀錄保留輸入資料，結果顯示「已停用」，不保留可能誤導的即時數值。
5. 支援多筆紀錄，同方向／同幣種可建立多筆；以穩定 ID 區別。清單預設依換幣時間由新到舊，同時間依 ID 穩定排序。

紀錄獨立於自選分組與手動持倉，不自動扣除／增加持倉；編輯持倉、切換或刪除分組不修改比較紀錄。每筆視為獨立情境，不加總成投資組合收益，避免重複資金與不同原幣單位造成誤解。

### 第一版採用的假設

- 使用者手動填寫一筆已發生的 A → B 換幣，B 數量固定，不自動追蹤後續加倉、減倉或收益。
- A 數量代表這次換出前用來比較的總數量；若另以 A 支付費用且要納入比較，應填入實際總扣除數量。
- B 數量填實際到帳淨數量，已從 B 扣除的首次換幣費用自然反映在數量中；不另重複扣除。
- 換幣時間用於紀錄與排序，不回查當時報價、不影響公式。預設現在，允許過去時間，拒絕未來時間；保存含時區時間，畫面以使用者本機時區顯示。
- 第一版結果是「未扣除換回費用的估算」：不計換回手續費、買賣價差、滑價或交易數量限制。以其他資產支付的首次費用也未納入。固定顯示此計算口徑。

### 不包含

自動下單、帳戶／API Key 串接、交易匯入、多段 A → B → C 換幣鏈、部分換回結算、已實現損益、換幣提醒、歷史曲線及手續費模型。這些可在後續 issue 擴充。

## 3. 公式與可重現範例

定義：

- QA：原本換出的 A 數量，必須 > 0。
- QB：實際換入的 B 數量，必須 > 0。
- PA：A 的最新有效 USDT 單價，必須 > 0。
- PB：B 的最新有效 USDT 單價，必須 > 0。

公式：

~~~text
原幣持有市值 VA = QA × PA
換入幣持有市值 VB = QB × PB
目前可換回原幣 RA = VB ÷ PA
原幣數量差額 ΔA = RA − QA
USDT 差額 ΔU = VB − VA
相對報酬率 R = (VB ÷ VA − 1) × 100%
~~~

ΔA > 0 表示可多換回原幣；ΔA < 0 表示少換回原幣。ΔU 與 ΔA 的正負方向相同，且數學上 ΔU = ΔA × PA。計算使用未經顯示四捨五入的 decimal 數值；顯示再依既有格式化規則處理，百分比顯示兩位小數。正值加 +，負值保留 −，零使用中性色；不可只靠顏色傳達方向，格式化後的負零統一顯示零。

以下皆為受控示例，非市場報價：

| QA | QB | PA | PB | 可換回 A | A 差額 | USDT 差額 | 相對報酬率 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 100 NEAR | 20 QNT | 5 | 30 | 120 NEAR | +20 NEAR | +100 USDT | +20% |
| 100 NEAR | 20 QNT | 5 | 20 | 80 NEAR | −20 NEAR | −100 USDT | −20% |
| 100 NEAR | 20 QNT | 5 | 25 | 100 NEAR | 0 NEAR | 0 USDT | 0% |

正收益範例的畫面文字：

~~~text
100 NEAR → 20 QNT
現在可換回：120 NEAR
換幣差額：+20 NEAR · +100 USDT · +20.00%
原幣若持有至今：500 USDT
換入幣現在市值：600 USDT
未扣除換回費用的估算
~~~

## 4. 輸入、行情與異常行為

### 輸入驗證

- 幣種沿用 SymbolNormalizer，接受 NEAR／NEARUSDT 等輸入；儲存成正規化 USDT 交易對。
- A 與 B 不得相同，且儲存新增／變更幣種時使用既有公開行情驗證流程確認兩個 USDT 現貨交易對有效。
- 數量必填且為正 decimal；拒絕零、負數、非數字、千分位逗號及超出 decimal 範圍。沿用小數點使用 . 的提示。
- 網路驗證失敗時保留未儲存的輸入，顯示錯誤並可重試；不可當作已儲存。
- 既存紀錄若後來無行情或交易對失效，保留紀錄並標示不可計算，不自動刪除。

### 行情訂閱與更新

延伸 MarketDemand.Quotes，將所有啟用比較紀錄的 A 與 B 加入共用訂閱集合，與自選、持倉及提醒需求去重。兩邊任一有效行情更新時，以快取中兩邊最近的報價重新計算。兩筆不要求完全同時到達，詳情明示各自時間，代表最近可用行情的交叉估算。

新增幣種即使不在任何自選分組或持倉中也必須取得報價。切換分組、隱藏主窗／比較視窗不停止啟用紀錄的行情需求。停用或刪除後移除該紀錄需求，但不能移除其他功能仍需要的訂閱。

### 資料品質與例外

- 缺少任一報價：相依比較結果顯示 — 及「等待 NEAR／QNT 報價」，不將缺報價視為零。
- 價格 <= 0 或未來時間的行情不可作為有效輸入；無有效快取時顯示 —。
- 斷線、連線中，或任一邊報價超過 60 秒未更新：若兩邊仍有有效快取，可計算但標示「使用最後報價」，並顯示兩邊時間；不得標為即時。恰好 60 秒沿用既有規則，不視為超過。
- 即使沒有新報價，狀態也必須隨時間更新為過期；恢復有效新報價後清除過期標記。
- 兩邊價格或數量運算超出 decimal 範圍：比較結果顯示 — 與「超出可計算範圍」，不崩潰、不顯示部分比較值為完整結果。
- 設定儲存失敗時保留編輯內容並顯示錯誤，已保存紀錄與有效訂閱維持原狀。

## 5. 資料模型與專案整合

建議 AppSettings 新增全域 SwapComparisons 清單，單筆資料：

| 欄位 | 型別／規則 |
| --- | --- |
| Id | 唯一且穩定的字串 ID |
| FromSymbol | 正規化 A/USDT 交易對 |
| FromQuantity | 正 decimal，QA |
| ToSymbol | 正規化 B/USDT 交易對 |
| ToQuantity | 正 decimal，QB，實際到帳量 |
| SwappedAt | DateTimeOffset，含時區 |
| Note | 選填文字 |
| Enabled | bool，預設 true |

僅持久化輸入與啟用狀態；衍生結果與報價不寫入設定。沿用 SettingsService 與 AtomicJsonFile 保存至本機 settings.json，Copy／Normalize 同步支援新欄位。舊設定缺欄位時採空清單；不得改動原有持倉、分組、提醒及視窗偏好。所有設定儲存路徑需保留最新比較資料，避免一般設定、警示與比較編輯互相覆蓋。

有效 JSON 中的個別無效比較紀錄應隔離並提示，其他設定繼續載入，禁止靜默丟棄或自動覆寫原檔；實作時需保存原檔備份，並要求使用者明確修正／移除無效紀錄後才允許會覆寫它的設定儲存。整份 JSON 無法解析則沿用現有損壞檔備份與載入警告機制。

復原可逐筆進行：明確修正／移除一筆時，其他未修正紀錄的原始 JSON 必須完整保留。
一般設定、提醒及偏好保存不得繞過此保護。重複 ID 的損壞紀錄使用獨立復原 ID，
避免刪除或編輯時波及正常紀錄；每次不同的損壞原檔保存獨立備份。

建議整合位置（實作可沿用現有命名慣例）：

- Core Models：SwapComparisonSetting 與比較結果模型。
- Core Services：純計算 SwapComparisonCalculator；MarketDemand 增加兩邊行情需求；SettingsService 整合驗證與保存。
- Core ViewModels：比較清單／編輯／行情狀態，注入時間來源方便驗證過期狀態。
- WPF Views／Services：比較視窗、視窗管理及入口；沿用現有主題與輔助視窗模式。
- Tests：計算、設定往返與遷移、訂閱去重與移除、編輯流程及視窗整合。

## 6. 驗收條件

- [ ] 可新增、編輯、取消、刪除、啟用／停用多筆獨立 A → B 比較紀錄，重啟後資料與方向不變。
- [ ] 100 NEAR → 20 QNT，NEAR=5、QNT=30 時，顯示可換回 120 NEAR、+20 NEAR、+100 USDT、+20.00%。
- [ ] QNT=20 時顯示 80 NEAR、−20 NEAR、−100 USDT、−20.00%；QNT=25 時四項結果符合打平範例。
- [ ] 明確標示「相較繼續持有原幣」及「未扣除換回費用的估算」，不混用平均成本損益。
- [ ] 驗證不同小數精度、極小正數、decimal 溢位與顯示負零；未四捨五入的值符合公式關係。
- [ ] 拒絕同幣種、空數量、零／負數量、無效交易對、錯誤時間與數字格式；錯誤不丟失未儲存輸入。
- [ ] 任一邊更新即重算；不在自選分組的幣種仍有行情；多筆與既有功能共享訂閱且去重。
- [ ] 停用／刪除紀錄只移除它的需求，不中斷其他紀錄、自選、持倉、提醒或行情詳情需求。
- [ ] 缺報價、零／負價格、未來行情、斷線、60 秒邊界與無新報價的過期轉換均有明確且正確顯示，重連後可恢復。
- [ ] 設定讀寫與 Copy 正確；舊設定不受影響；個別無效紀錄、損壞檔、寫入失敗有資料保護；不同編輯視窗互不覆蓋。
- [ ] 切換分組、修改持倉與隱藏主窗不改變比較基準；不同原幣紀錄不直接加總。
- [ ] 深／淺色、Fix／Float、最小視窗及長清單操作可用，正負方向有文字／符號提示。
- [ ] 以受控行情與時間完成自動驗證，並實機檢查新增／編輯／取消／停用／重啟／斷線畫面。
